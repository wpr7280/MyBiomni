# WarpHelix Agent 应用数据库表清单

## 概述

本文档列出了 WarpHelix Agent 应用的所有数据库表，共 **14 张表**。

---

## 1. 用户管理模块 (2张)

### 1.1 admins - 管理员表
**用途**: 存储系统管理员账号信息

**核心字段**:
- `username` - 用户名
- `password` - 密码（BCrypt加密）
- `email` - 邮箱
- `role` - 角色（super_admin, admin）
- `force_password_change` - 强制修改密码标记

**索引**:
- 主键: `id`
- 唯一索引: `username`, `email`

### 1.2 users - 用户表
**用途**: 存储普通用户账号信息

**核心字段**:
- `username` - 用户名
- `password` - 密码（BCrypt加密）
- `email` - 邮箱
- `phone` - 手机号
- `status` - 状态（启用/禁用）

**索引**:
- 主键: `id`
- 唯一索引: `username`, `email`, `phone`

---

## 2. 配置管理模块 (2张)

### 2.1 system_configs - 系统配置表
**用途**: 存储系统全局配置

**核心字段**:
- `config_key` - 配置键
- `config_value` - 配置值（JSON格式）
- `config_type` - 配置类型（system, model, commercial）
- `is_encrypted` - 是否加密

**配置类型**:
- `commercial_mode` - 商用模式配置
- `default_model` - 默认模型配置
- `system_settings` - 系统基础配置

**索引**:
- 主键: `id`
- 唯一索引: `config_key`

### 2.2 config_change_logs - 配置变更日志表
**用途**: 记录配置变更历史

**核心字段**:
- `config_id` - 配置ID
- `old_value` - 旧值
- `new_value` - 新值
- `operator_id` - 操作人ID
- `change_reason` - 变更原因

**索引**:
- 主键: `id`
- 普通索引: `config_id`, `operator_id`

---

## 3. 配额管理模块 (3张)

### 3.1 quota_templates - 配额模板表
**用途**: 定义配额模板

**核心字段**:
- `template_name` - 模板名称
- `daily_conversation_limit` - 每日对话限制
- `monthly_conversation_limit` - 每月对话限制
- `daily_token_limit` - 每日Token限制
- `monthly_token_limit` - 每月Token限制
- `concurrent_task_limit` - 并发任务限制
- `storage_limit_mb` - 存储空间限制

**预设模板**:
- 免费版
- 基础版
- 专业版
- 企业版

**索引**:
- 主键: `id`
- 唯一索引: `template_name`

### 3.2 user_quotas - 用户配额表
**用途**: 存储用户的配额分配

**核心字段**:
- `user_id` - 用户ID
- `template_id` - 配额模板ID
- 各项配额限制字段
- `effective_from` - 生效开始时间
- `effective_until` - 生效结束时间

**索引**:
- 主键: `id`
- 唯一索引: `user_id`
- 外键: `user_id` → `users.id`, `template_id` → `quota_templates.id`

### 3.3 quota_usage_records - 配额使用记录表
**用途**: 记录用户配额使用情况

**核心字段**:
- `user_id` - 用户ID
- `record_date` - 记录日期
- `daily_conversation_used` - 当日对话次数
- `monthly_conversation_used` - 当月对话次数
- `daily_token_used` - 当日Token使用量
- `monthly_token_used` - 当月Token使用量

**索引**:
- 主键: `id`
- 唯一索引: `(user_id, record_date)`
- 外键: `user_id` → `users.id`

---

## 4. 对话管理模块 (3张)

### 4.1 conversations - 对话表
**用途**: 存储用户对话信息

**核心字段**:
- `user_id` - 用户ID
- `title` - 对话标题
- `status` - 状态（active, completed, failed, cancelled）
- `model_name` - 使用的模型
- `message_count` - 消息数量
- `total_tokens` - 总Token消耗
- `total_duration_ms` - 总执行时长

**索引**:
- 主键: `id`
- 普通索引: `user_id`, `status`, `created_at`
- 外键: `user_id` → `users.id`

### 4.2 messages - 消息表
**用途**: 存储对话中的消息

**核心字段**:
- `conversation_id` - 对话ID
- `role` - 角色（user, assistant, system）
- `content` - 消息内容
- `content_type` - 内容类型（text, markdown, code）
- `tokens` - Token消耗

**索引**:
- 主键: `id`
- 普通索引: `conversation_id`, `created_at`
- 外键: `conversation_id` → `conversations.id`

### 4.3 execution_steps - 执行步骤表
**用途**: 记录 Agent 执行的详细步骤

**核心字段**:
- `conversation_id` - 对话ID
- `message_id` - 消息ID
- `step_order` - 步骤顺序
- `step_type` - 步骤类型（reasoning, tool_call, result）
- `tool_name` - 工具名称
- `tool_input` - 工具输入
- `tool_output` - 工具输出
- `status` - 状态（running, success, failed）
- `duration_ms` - 执行时长

**索引**:
- 主键: `id`
- 普通索引: `conversation_id`, `message_id`, `(conversation_id, step_order)`
- 外键: `conversation_id` → `conversations.id`, `message_id` → `messages.id`

---

## 5. Know-How 文档管理模块 (2张)

### 5.1 knowhow_documents - Know-How 文档表
**用途**: 存储 Know-How 文档

**核心字段**:
- `doc_id` - 文档唯一标识（文件名）
- `title` - 文档标题
- `short_description` - 简短描述
- `content` - 文档内容（Markdown）
- `content_without_metadata` - 去除元数据的内容
- `category` - 分类（字符串）
- `tags` - 标签（逗号分隔）
- `authors` - 作者
- `license` - 许可证
- `commercial_use` - 商用许可（0-不允许, 1-允许）
- `status` - 状态（0-禁用, 1-启用, 2-草稿）
- `priority` - 优先级
- `view_count` - 查看次数
- `usage_count` - 使用次数

**预设分类**:
- 实验技术 (Lab Protocols)
- 数据分析 (Data Analysis)
- 疾病诊断 (Disease Diagnosis)
- 药物研发 (Drug Development)
- 生物信息学 (Bioinformatics)

**索引**:
- 主键: `id`
- 唯一索引: `doc_id`
- 普通索引: `category`, `status`, `commercial_use`, `priority`
- 全文索引: `(title, short_description, content)`

### 5.2 knowhow_document_versions - 文档版本历史表
**用途**: 记录文档的版本历史

**核心字段**:
- `document_id` - 文档ID
- `version_number` - 版本号
- `content` - 文档内容快照
- `change_summary` - 变更摘要
- `editor_id` - 编辑者ID
- `editor_type` - 编辑者类型（admin, system）

**索引**:
- 主键: `id`
- 普通索引: `(document_id, version_number)`, `(editor_id, editor_type)`
- 外键: `document_id` → `knowhow_documents.id`

---

## 6. 日志审计模块 (2张)

### 6.1 operation_logs - 操作日志表
**用途**: 记录用户和管理员的操作日志

**核心字段**:
- `operator_id` - 操作人ID
- `operator_type` - 操作人类型（admin, user, system）
- `operation_type` - 操作类型（create, update, delete, login, logout）
- `operation_module` - 操作模块（user, config, conversation, knowhow）
- `operation_desc` - 操作描述
- `request_method` - 请求方法
- `request_url` - 请求URL
- `request_ip` - 请求IP
- `response_status` - 响应状态码
- `error_message` - 错误信息

**索引**:
- 主键: `id`
- 普通索引: `(operator_id, operator_type)`, `operation_type`, `operation_module`, `created_at`

### 6.2 login_logs - 登录日志表
**用途**: 记录登录日志

**核心字段**:
- `user_id` - 用户ID
- `user_type` - 用户类型（admin, user）
- `username` - 用户名
- `login_type` - 登录方式（password, code, oauth）
- `login_status` - 登录状态（success, failed）
- `fail_reason` - 失败原因
- `ip_address` - IP地址
- `location` - 地理位置
- `user_agent` - User Agent
- `device_type` - 设备类型
- `browser` - 浏览器
- `os` - 操作系统

**索引**:
- 主键: `id`
- 普通索引: `(user_id, user_type)`, `login_status`, `created_at`

## 7. 表关系图

```
users (用户)
  ├─→ user_quotas (配额)
  │     └─→ quota_templates (配额模板)
  ├─→ conversations (对话)
  │     ├─→ messages (消息)
  │     └─→ execution_steps (执行步骤)
  └─→ quota_usage_records (配额使用记录)

admins (管理员)
  └─→ operation_logs (操作日志)

knowhow_documents (文档)
  └─→ knowhow_document_versions (文档版本)

system_configs (系统配置)
  └─→ config_change_logs (配置变更日志)

login_logs (登录日志)
```

## 9. 存储估算

### 9.1 小规模部署（100 用户）
- 用户数据: ~10 MB
- 对话数据: ~500 MB（假设每用户 100 条对话）
- 文档数据: ~50 MB（50 个文档）
- 日志数据: ~100 MB（保留 3 个月）
- **总计**: ~660 MB

### 9.2 中规模部署（1000 用户）
- 用户数据: ~100 MB
- 对话数据: ~5 GB
- 文档数据: ~100 MB
- 日志数据: ~1 GB
- **总计**: ~6.2 GB

### 9.3 大规模部署（10000 用户）
- 用户数据: ~1 GB
- 对话数据: ~50 GB
- 文档数据: ~200 MB
- 日志数据: ~10 GB
- **总计**: ~61 GB

## 10. 性能优化建议

### 10.1 索引优化
- ✅ 所有外键都有索引
- ✅ 高频查询字段都有索引
- ✅ 复合索引覆盖常见查询

### 10.2 分区建议
对于大规模部署，建议对以下表进行分区：
- `operation_logs` - 按月分区
- `login_logs` - 按月分区
- `quota_usage_records` - 按月分区
- `execution_steps` - 按季度分区

### 10.3 归档策略
- 操作日志: 保留 3 个月，之后归档
- 登录日志: 保留 6 个月，之后归档
- 对话记录: 保留 1 年，之后归档或删除
- 配额使用记录: 保留 1 年
