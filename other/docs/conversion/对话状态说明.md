# 对话状态 (status) 详细说明

## 1. 状态定义

```sql
`status` VARCHAR(20) NOT NULL DEFAULT 'active' 
COMMENT '状态: active-进行中, completed-已完成, failed-失败, cancelled-已取消'
```

---

## 2. 状态详解

### 2.1 active（进行中）

**含义**：对话正在进行中，用户可以继续发送消息

**使用场景**：
- ✅ 创建新对话时的默认状态
- ✅ 用户正在与 Agent 交互
- ✅ 对话尚未结束

**状态转换**：
```
创建对话 → active
active → completed（用户主动结束）
active → failed（执行失败）
active → cancelled（用户取消）
```

**示例**：
```sql
INSERT INTO conversations (user_id, title, status) 
VALUES (1, '新对话', 'active');
```

---

### 2.2 completed（已完成）

**含义**：对话已正常完成，用户不再继续提问

**使用场景**：
- ✅ 用户得到满意的答案
- ✅ 问题已解决
- ✅ 用户主动标记为完成

**状态转换**：
```
active → completed（用户点击"完成"按钮）
```

**前端展示**：
- 对话列表中显示 ✅ 图标
- 可以查看历史记录
- 可以重新激活（completed → active）

**示例**：
```sql
UPDATE conversations 
SET status = 'completed', updated_at = NOW()
WHERE id = 1;
```

---

### 2.3 failed（失败）

**含义**：对话执行过程中发生错误，无法继续

**使用场景**：
- ❌ Agent 执行失败
- ❌ 系统错误
- ❌ 配额不足
- ❌ 超时

**状态转换**：
```
active → failed（执行过程中出错）
```

**前端展示**：
- 对话列表中显示 ❌ 图标
- 显示错误信息
- 可以重试（failed → active）

**示例**：
```sql
UPDATE conversations 
SET status = 'failed', updated_at = NOW()
WHERE id = 1;
```

---

### 2.4 cancelled（已取消）

**含义**：用户主动取消了对话

**使用场景**：
- 🚫 用户不想继续这个对话
- 🚫 用户点击"取消"按钮
- 🚫 用户中断了执行

**状态转换**：
```
active → cancelled（用户主动取消）
```

**前端展示**：
- 对话列表中显示 🚫 图标
- 可以查看历史记录
- 可以重新激活（cancelled → active）

**示例**：
```sql
UPDATE conversations 
SET status = 'cancelled', updated_at = NOW()
WHERE id = 1;
```

## 4. 前端使用

### 4.1 TypeScript 类型定义

```typescript
type ConversationStatus = 'active' | 'completed' | 'failed' | 'cancelled';

interface Conversation {
  id: number;
  title: string;
  status: ConversationStatus;
  messageCount: number;
  // ...
}
```

### 4.2 状态图标映射

```typescript
const statusIcons = {
  active: '💬',      // 进行中
  completed: '✅',   // 已完成
  failed: '❌',      // 失败
  cancelled: '🚫',   // 已取消
};

const statusColors = {
  active: 'blue',
  completed: 'green',
  failed: 'red',
  cancelled: 'default',
};
```

### 4.3 状态显示

```tsx
<Tag color={statusColors[conversation.status]}>
  {statusIcons[conversation.status]} {conversation.status}
</Tag>
```

## 5. 业务逻辑

### 5.1 创建对话

```java
Conversation conversation = new Conversation();
conversation.setUserId(userId);
conversation.setTitle(title);
conversation.setStatus("active");  // 默认状态
conversationRepository.save(conversation);
```

### 5.2 完成对话

```java
// 用户点击"完成"按钮
conversation.setStatus("completed");
conversationRepository.save(conversation);
```

### 5.3 执行失败

```python
# Python Agent 执行失败时
try:
    result = agent.go(query)
except Exception as e:
    # 更新对话状态为 failed
    db.query(Conversation).filter(
        Conversation.id == conversation_id
    ).update({
        'status': 'failed'
    })
```

### 5.4 用户取消

```java
// 用户点击"取消"按钮
conversation.setStatus("cancelled");
conversationRepository.save(conversation);
```

## 6. 查询示例

### 6.1 只查询进行中的对话

```sql
SELECT * FROM conversations
WHERE user_id = ? 
  AND status = 'active'
  AND deleted_at IS NULL
ORDER BY updated_at DESC;
```

### 6.2 查询所有对话（包含状态筛选）

```sql
SELECT * FROM conversations
WHERE user_id = ?
  AND deleted_at IS NULL
  AND (? IS NULL OR status = ?)  -- 可选的状态筛选
ORDER BY updated_at DESC;
```

### 6.3 统计各状态的对话数量

```sql
SELECT 
  status,
  COUNT(*) as count
FROM conversations
WHERE user_id = ? AND deleted_at IS NULL
GROUP BY status;
```

## 8. 总结

### 状态用途

| 状态 | 用途 | 是否可继续对话 | 前端图标 |
|------|------|----------------|----------|
| active | 正常进行中 | ✅ 是 | 💬 |
| completed | 用户标记完成 | ❌ 否（可重新激活） | ✅ |
| failed | 执行失败 | ❌ 否（可重试） | ❌ |
| cancelled | 用户取消 | ❌ 否（可重新激活） | 🚫 |

### 建议

- ✅ **简化版本**：只使用 `active` 和 `completed`
- ✅ **完整版本**：使用所有四个状态
- ✅ **扩展版本**：可以添加更多状态（如 `archived`）

根据实际需求选择合适的状态管理策略！
