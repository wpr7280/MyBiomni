# WarpHelix Agent 应用部署需求文档

## 1. 项目概述

### 1.1 项目背景
WarpHelix 是一个通用的生物医学 AI Agent，目前已完成核心 Agent 功能开发。本项目旨在将 WarpHelix Agent 封装为完整的 SaaS 应用，提供管理后台和用户客户端，实现商业化部署。

### 1.2 项目目标
- 构建完整的用户管理和权限体系
- 提供灵活的配置管理和商用控制
- 实现对话历史追踪和系统监控
- 支持 Know-How 文档的动态管理
- 提供友好的用户交互界面

### 1.3 技术栈
- **后端**: Spring Boot 3.x + MySQL 8.0 + Redis
- **前端**: React 18 + TypeScript + Ant Design / Vue 3 + TypeScript + Element Plus
- **Agent**: Python (现有 WarpHelix Agent)
- **部署**: Docker + Kubernetes

## 3. Admin 管理端需求

### 3.1 用户认证与管理

#### 3.1.1 系统初始化
**功能描述**: 系统首次启动时自动初始化

**功能点**:
- 自动创建默认管理员账号
- 用户名: `admin`
- 随机生成初始密码 (16位强密码)
- 初始密码输出到控制台日志
- 首次登录强制修改密码
- 初始化标记 (防止重复初始化)

**初始化流程**:
1. 检查数据库是否已初始化 (检查 admins 表是否有记录)
2. 如未初始化，创建默认管理员账号
3. 生成随机密码并加密存储
4. 设置 `force_password_change` 标记为 true
5. 输出初始密码到日志: `[INIT] Default admin password: xxxxxxxxxxxxxxxx`
6. 记录初始化完成标记

**安全要求**:
- 初始密码必须包含大小写字母、数字、特殊字符
- 初始密码长度 16 位
- 首次登录后必须修改密码才能使用系统
- 初始密码仅在控制台显示一次

#### 3.1.2 管理员登录
**功能描述**: 管理员通过用户名密码登录系统

**功能点**:
- 用户名/密码登录
- JWT Token 认证
- 登录日志记录
- 密码加密存储 (BCrypt)
- 登录失败锁定机制 (5次失败锁定30分钟)
- 记住登录状态 (7天)
- 首次登录强制修改密码

**接口**:
- `POST /api/admin/auth/login` - 登录
- `POST /api/admin/auth/logout` - 登出
- `POST /api/admin/auth/refresh` - 刷新 Token
- `GET /api/admin/auth/info` - 获取当前管理员信息
- `POST /api/admin/auth/change-password` - 修改密码 (首次登录强制)

#### 3.1.2 用户管理
**功能描述**: 管理系统用户账号

**功能点**:
- 用户列表查询 (分页、搜索、筛选)
- 用户详情查看
- 创建用户账号
- 编辑用户信息
- 禁用/启用用户
- 重置用户密码
- 用户角色分配
- 批量操作

**用户字段**:
- 基本信息: 用户名、邮箱、手机号、真实姓名
- 状态: 启用/禁用、认证状态
- 配额: 对话次数、Token 使用量
- 时间: 注册时间、最后登录时间

**接口**:
- `GET /api/admin/users` - 用户列表
- `GET /api/admin/users/{id}` - 用户详情
- `POST /api/admin/users` - 创建用户
- `PUT /api/admin/users/{id}` - 更新用户
- `DELETE /api/admin/users/{id}` - 删除用户
- `PUT /api/admin/users/{id}/status` - 修改状态
- `POST /api/admin/users/{id}/reset-password` - 重置密码

### 3.2 全局配置管理

#### 3.2.1 商用模式配置
**功能描述**: 控制系统是否启用商用模式，影响数据集和工具的可用性

**配置项**:
- `commercial_mode`: 是否启用商用模式 (boolean)
- `commercial_mode_description`: 商用模式说明
- 生效范围: 全局

**功能点**:
- 开关商用模式
- 商用模式影响说明
- 配置变更日志
- 配置生效时间

**参考**: `agent/biomni/config.py` 中的 `commercial_mode`

#### 3.2.2 模型配置
**功能描述**: 配置系统使用的 LLM 模型

**配置项**:

- `llm`: 模型名称 (如 "claude-sonnet-4-5", "gpt-4", "azure-gpt-4o")
- `source`: 模型来源 (OpenAI, Anthropic, Azure, Gemini, Bedrock, Groq, Custom)
- `temperature`: 温度参数 (0.0-1.0)
- `base_url`: 自定义模型 API 地址
- `api_key`: 自定义模型 API Key (加密存储)
- `timeout_seconds`: 超时时间 (秒)

**功能点**:
- 模型配置表单
- API Key 安全存储
- 配置测试连接
- 多模型配置支持
- 默认模型设置

**接口**:
- `GET /api/admin/config/model` - 获取模型配置
- `PUT /api/admin/config/model` - 更新模型配置
- `POST /api/admin/config/model/test` - 测试模型连接

#### 3.2.3 系统配置
**功能描述**: 其他系统级配置

**配置项**:
- `data_path`: 数据存储路径
- `use_tool_retriever`: 是否使用工具检索
- `max_concurrent_tasks`: 最大并发任务数
- `session_timeout`: 会话超时时间 (分钟)
- `enable_registration`: 是否开放用户注册
- `default_user_quota`: 新用户默认配额

**接口**:
- `GET /api/admin/config/system` - 获取系统配置
- `PUT /api/admin/config/system` - 更新系统配置

### 3.3 用户配额管理

#### 3.3.1 配额配置
**功能描述**: 为用户设置使用配额限制

**配额类型**:
- **对话次数配额**: 每日/每月可创建的对话数量
- **Token 配额**: 每日/每月可使用的 Token 总量
- **并发限制**: 同时运行的 Agent 任务数
- **存储配额**: 对话历史存储空间限制

**配额维度**:
- 用户级别配额 (单个用户)
- 角色级别配额 (用户组)
- 全局默认配额

**功能点**:
- 配额模板管理
- 批量配额分配
- 配额使用统计
- 配额重置 (按周期)
- 配额预警通知

**接口**:
- `GET /api/admin/quota/templates` - 配额模板列表
- `POST /api/admin/quota/templates` - 创建配额模板
- `PUT /api/admin/users/{id}/quota` - 设置用户配额
- `GET /api/admin/users/{id}/quota/usage` - 查看配额使用情况
- `POST /api/admin/quota/reset` - 重置配额

### 3.4 对话记录查看

#### 3.4.1 对话列表
**功能描述**: 查看所有用户的对话记录

**功能点**:

- JWT Token 认证

- CSRF 防护
- 敏感操作审计日志
- 数据备份策略

### 5.3 可用性要求
- 系统可用性: 99.9%
- 数据持久化
- 故障自动恢复

### 5.4 可扩展性
- 微服务架构
- 水平扩展支持
- 负载均衡
- 缓存策略

### 5.5 兼容性
- 浏览器: Chrome, Firefox, Safari, Edge (最新两个版本)

- API 版本管理

## 6. 技术实现要点

### 6.1 后端技术选型
- **框架**: Spring Boot 3.2+
- **数据库**: MySQL 8.0
- **缓存**: Redis 7.0
- **消息队列**: RabbitMQ / Kafka (可选)
- **ORM**: MyBatis-Plus / JPA
- **认证**: Spring Security + JWT
- **API 文档**: Swagger / OpenAPI 3.0
- **日志**: SLF4J + Logback
- **监控**: Prometheus + Grafana

### 6.2 前端技术选型
- **框架**: React 18 + TypeScript / Vue 3 + TypeScript
- **UI 库**: Ant Design / Element Plus
- **状态管理**: Redux Toolkit / Pinia
- **HTTP 客户端**: Axios
- **实时通信**: WebSocket / Server-Sent Events
- **图表**: ECharts / Chart.js
- **Markdown**: react-markdown / marked
- **代码高亮**: Prism.js / highlight.js

### 6.3 Agent 集成
- **通信方式**: REST API / gRPC
- **任务队列**: Celery / RQ
- **异步处理**: 消息队列
- **状态同步**: WebSocket
- **文件存储**: MinIO / OSS

### 6.4 部署方案
- **容器化**: Docker
- **编排**: Kubernetes / Docker Compose
- **CI/CD**: GitLab CI / GitHub Actions
- **监控**: Prometheus + Grafana + ELK
- **日志**: ELK Stack (Elasticsearch, Logstash, Kibana)
